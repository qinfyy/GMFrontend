### 修掉的真实 bug

传承篇 / 新生篇是单空格分隔行：`第一章 L1-1 8351 type=1 GM=/storycompleted 8351 [@uid]`。
旧代码用 `line.split(/\s+/)` 切列，而 `GM=` 的值**含空格且总是行尾**，结果：
- `attrs['GM']` 只拿到 `/storycompleted`（被截断）
- 尾部 token `8351`、`[@uid]` 被追加进 `name` → 「第一章 L1-1 8351 [@uid]」

修法：新增 `parseAttrs()`，先用 `/(?:^|\s)GM=(.*)$/` 把 GM 整段取出，再解析其余 key=value；章节行改用正则 `^(第\S+)\s+(\S+)\s+(\d+)\s+(.*)$`。

### 关键认知：Args vs PositionalArgs

服务端 `CommandContext` 把命令名之后的 token 分两份：
- `Args`：只剔除 `@uid` 与 `-flag`，**保留**数值型修饰符（`lv5`/`r123`…）
- `PositionalArgs`：再剔除全部修饰符，`GetArg(n)`/`RequireArg(n)` 基于它

后果：**kick 的提示正文、ban 的封禁理由里不能出现 `x1`/`lv80`/`r5`/`t99`/`-x`/`@…` 形态的片段**，否则被静默剔除。`/ban` 的 `t结束时间`/`r理由` 正是靠 `Args` 存活（两者都不是纯数字，不命中通用修饰符）。前端在 `moderation.page.ts` 的 `warning()` 里做了发送前拦截。

### 验证手法（可复用）

1. **本机有 `http_proxy`**，打 localhost 必须加 `--noproxy '*'`，否则拿到代理的错误页（曾被骗过一次）。
2. **离线验证 `handbook.service.ts`**：用项目自带的 esbuild 把 TS 打包成 node 脚本，`--alias:@angular/core=./stub-core.js` 提供 `Injectable`/`signal` 空实现，入口里 stub `globalThis.fetch` 让它读本地 `public/Handbook.txt`，然后 `new HandbookService().load()` + `section()` 断言。不需要起浏览器。
3. **破坏性命令的非破坏性测法**：kick/ban 全部打在不存在的 UID `999999999` 上——kick 会先被 `RequireTargetOnline` 拦成 400「目标玩家 … 不存在或不在线」，ban 会走到 `GetTargetPlayer` 抛 404 `player_not_found`，两者都能证明参数解析正确且不产生副作用。
